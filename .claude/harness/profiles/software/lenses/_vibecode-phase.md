## Phase 2 — Parallel audit by signature family

Launch the auditors of the retained families **in a single message**: three cover the `securite` axis, one per remaining axis (VA-01).

- **(a) `acces`** (`ACC-`, security) — **access control absent or deferred to the client**: access to another user's resource by substituting an identifier, with no server-side ownership check; no notion of role, or role declared by the client and taken on faith; unprotected admin endpoints; mass assignment letting the client write privileged fields; control present in the interface only. Common cause: *generation writes the nominal path, and authorization is never in the request*.
- **(b) `injection`** (`INJ-`, security) — **untrusted input treated as code, unescaped outputs**: queries or commands built by concatenation; path traversal; template injection; deserialization of untrusted input; user content inserted without escaping, including deferred via a persisted field; forged requests when the session is carried by the browser; validation never replayed server-side; debug or bootstrap endpoints left active; errors revealing the implementation. Typical pattern: *the safe abstraction is used everywhere except on the complicated query*.
- **(c) `metier`** (`MET-`, security) — **domain invariants never enforced**: finite resource assignable twice (uniqueness, transaction, lock absent) or exceeded by concurrent requests; amounts, quantities, discounts, owner supplied by the client and accepted as is; state transitions without checking the starting state; no throttling on authentication or costly operations, enumeration possible; personal data collected beyond what is necessary, authentication secrets without robust derivation, personal data in logs, no retention period or deletion; no usable trace after an incident. **The most profitable family and the least covered by tooling**: it requires reconstructing rules written nowhere.
- **(d) `maintenabilite`** (`MNT-`) — **inconsistencies between generation sessions**, first the **cross-cutting work, invisible file by file**: the same function written several times under different names; the same business rules in the interface and on the server with silent divergences; the same entity described differently on either side of the network. Then: contracts so broad they constrain nothing; abandoned leads; tests absent or whose assertions target the doubles; errors caught without handling; discontinuous style; comments that paraphrase the code.
- **(e) `evolutivite`** (`EVO-`) — **choices that block what comes next**: data structure modified without a replayable or reversible migration; third-party service called everywhere without an abstraction boundary; polling in a loop, unpaginated reads, missing indexes; hard-coded addresses, identifiers, thresholds instead of externalized ones; long or fallible processing in the request cycle; code assuming one user at a time where the domain guarantees the opposite.

Each prompt contains: the map (trust boundaries included), **its family and nothing else**, the reading budget, the sentence "**zero findings is a normal and acceptable answer**", the ban on writing or executing, the ban on naming a stack, verifiable evidence, the difficulty scale — **an order of magnitude, not an estimate**: XS < 30 min, S < 2 h, M half a day, L 1-2 days, XL to be split; when in doubt, the larger one — and a single final JSON block (VA-04):

```json
{"findings": [{"id": "ACC-01", "axis": "securite|maintenabilite|evolutivite",
  "pattern": "statement of the pattern in one sentence, no tech name", "severity": "critical|major|minor",
  "occurrences": [{"file": "relative/path", "line": 42, "evidence": "excerpt ≤ 3 lines"}],
  "count": 12, "sampled": true, "impact": "what an attacker or a maintainer can concretely do with it",
  "remediation": "fix of the pattern in one sentence — the class, not one occurrence",
  "difficulty": "XS|S|M|L|XL", "regression_risk": "faible|moyen|eleve",
  "risk_rationale": "what grounds this level: test coverage, number of callers, reach", "depends_on": []}]}
```

`occurrences`: up to 5 representative examples, `count` the real total, `sampled: true` beyond (the core normalizes). `critical` is reserved for what is remotely exploitable without authentication, exposes or destroys other people's data, or violates a domain invariant with direct business consequence. `difficulty` estimates the whole pattern. `regression_risk` is **informative**: it enters no sort, and `risk_rationale` grounds it in facts observed in this project — on a project without tests, answering `eleve` everywhere teaches nothing: grade relative to the other patterns.

Each return: `K audit auditor --run <run> --unit <family> --output <file> [--dead] --duration-ms <ms> --tokens <n>`. **A silent family is never a healthy family**: `relaunch` (once), then `surface` (VA-05: `major` unauditable surface, `bruts = échec`, announced at the top of the report). `validate` returns `to_validate`, `duplicates` (discarded without a validator) and `merge` (VA-07: duplicate between two auditors, **never discarded at random** — merge into one pattern with the most precise wording, the union of occurrences and the highest severity; count and difficulty are not arbitrated here: pass both estimates to the validator, require it to decide with figures verified at the source — `corrected_count` — and invite it to split if the gap signals a pattern that is too coarse).
