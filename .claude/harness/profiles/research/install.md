## Phase 1 — Research project detection

**1a. Stack.** `K stack detect --root .` (ST-01) returns markers, manifests and stacks. Read the manifests to extract the **framework** (PyTorch, JAX, TensorFlow, pure NumPy, `transformers`…), the **test command** (the one documented in `CLAUDE.md` or `README.md` if present), the lint command if configured, and the **project interpreter** (`.venv/`, `venv/`, conda env from `environment.yml`). Detect the declared **target hardware** ("GPU", "CUDA", "MPS", "CPU only", VRAM) and check its real availability with the project interpreter (e.g. `torch.cuda.is_available()`): agents must know whether an experiment runs on CPU or GPU.

**1b. Scientific corpus.** Read `CLAUDE.md`, `README.md` and `docs/` to retain the **exact paths** of: the **experiment journal** (dated entries; note the **exact format of an entry**, pre-registered protocols included, to reproduce it identically); the **architecture document** (mechanism maths, numbered decisions, pitfalls, eval protocol); the **roadmap** (candidate mechanisms with triggers, results table, the rule "one mechanism = one config flag, disabled by default, ablatable"); the **raw notes and frozen documents** that `CLAUDE.md` declares must not be modified (readable and citable, never editable); the vision if any. Also note: the project **vocabulary**, the **evals** (`eval/`, `experiments/`, `benchmarks/`: measured question, metric, control, real `argparse` options), the central **configuration class**, the **current state** ("État du projet"), the **non-negotiable constraints** ("no backprop", "one mechanism at a time", "baseline before any addition", "fp32 for memory", "SPDX"…), copied verbatim into the Director, Builder and Verifier prompts. Without a journal: `/lab-run` will create `docs/JOURNAL.md` (dated format), to be reported. Without a test command: the Builder will initialize `pytest`, to be reported.

**1c. Domain.** Infer from the documents the domain (bio-inspired mechanisms, associative memory, test-time training, architectures, optimization, RL…) and the **cited references**, so that the experts anchor on the same bibliography and do not reinvent what the project has dismissed.

## Phase 2b — Model assignment per role (AL-05, AL-06)

Agents are installed with only the core's `model:` block; the assignment lives in `.claude/models.json`, keys `lab.*` (X2), read at each cycle. A legacy `.claude/lab-models.json` is **migrated without being modified** (`K models resolve --root . --roles lab` writes `models.json` with `lab.`-prefixed keys).

Gate `ai-lab.models` (one call, remind that inherited roles consume the session's model and that the budget of the most capable model is spent quickly): **All inherited** (default) / **Most capable on both experts** (`neuro`, `math` on `fable`) / **Most capable on interpretation** (`math` and `director.interpretation` on `fable`; the most economical profile) / **Custom** (second call, one question per role `director.cadrage`, `director.interpretation`, `neuro`, `math`, `builder`, `verifier`, options `inherit` / `opus` / `fable` / `sonnet` / `haiku`). Write: `K models write --root . --preset lab-inherit|lab-experts|lab-interpretation|lab-custom [--set "lab.math=fable;…"]` — merge: missing keys completed, existing keys preserved. `inherit` = no override (parameter not passed); an unknown value in the file is treated as `inherit` with a warning, in `--models` it is an error (X8). `lab.validator` serves the mini-challenges (including `/ai-lab-audit`): keep it economical. Point out that the file is a personal setting (versionable or ignored, without deciding).

## Phase 4 — Core, headless scripts and merges

- **Core** (AL-08): `K sf copy-core --root .` copies `_core` under `.claude/harness/` (no bytecode, versioned); if an existing file differs, exit 1: stop by displaying the message, without generating the rest.
- **Scripts `ci/lab.sh` and `ci/lab.ps1`** (AL-07): `K lab ci --root . --allow "Bash(<PY> *)" --allow "<detected test command>" …` renders two equivalent scripts from the core template: protocol as mandatory argument, `--yolo` option (`-Yolo`), check of the `Status: PRE-REGISTERED` line, `--max-turns 150`, allowlist (`Read`, `Glob`, `Grep`, `Write`, `Edit`, `Bash(git *)` plus the `--allow`s, only those detected), output to `lab-logs/lab-<timestamp>.json`, `claude` exit code propagated.
- **Merges** (AL-01 to AL-03): `K lab apply --root . --test-command "<test command>" [--test-windows "<variant>"]` merges `.claude/settings.json` (`permissions.deny`: Python rules, generic `lab-logs/`, `experiments/results/`, `.git/objects/`, and data, weights and caches **present** only; the session never loads raw results, the Builder summarizes them and the Verifier recomputes them), `.vscode/tasks.json` (input `labProtocol`, tasks "Lab: run headless", "Lab: run headless (YOLO)", "Lab: tests unitaires", "Lab: nouvelle expérience (session)") and `.gitignore` (`lab-logs/`, `experiments/results/`, `.harness/runs/`). The `experiments/EXP-*.md` protocols are versioned: they are the pre-registration trail.

## Phase 5 — Knowledge base (optional)

A lab accumulates what was measured and why a lead was abandoned; the `code-index` skill makes this **queryable** (versioned index under `.knowledge/`, notes shared via git): a Director that queries the notes before framing will not re-propose an experiment already done. Gate `ai-lab.code-index` (*install* / *decline*); on agreement, invoke `code-index`, which detects the lab and wires the five agents and `/lab-run` by itself. **Never install without agreement** (the base adds a versioned folder); in headless, install nothing.

## Phase 6 — Final report

Detected project (stack, framework, interpreter, hardware and real GPU, test command); retained corpus (paths of the journal, architecture, roadmap, frozen documents, evals, config class, copied constraints); domain and references; files and their state (created / merged / identical / customized-kept), `.claude/harness/` included; **model assignment** (role → model table, `.claude/models.json`, migration of `lab-models.json` if any, editable by editing that file or one-off via `/lab-run "…" --models "math=opus"`, versionable or ignored); absence of journal or test tooling; usage (session: `/lab-run "question"` or `/lab-run suivant`; headless: `ci/lab.sh experiments/EXP-x.md`). If `$ARGUMENTS` contained a question, conclude with `/lab-run "<the question>"`.
